# Spaces publication

Use connected Pages tools supplied by the host; the local server has no Spaces credentials and does not call undocumented endpoints. The plugin's `.app.json` declares the Pages dependency. Tool availability is required for publication. Keep local artifacts recoverable when disconnected.

1. Get `meeting_status` and read the configured Meetings parent through `read_page`. If it is inaccessible, report the blocked destination; do not silently publish elsewhere. The saved target is an account-specific default; for another account, locate/create its intended Meetings Page and change configuration deliberately.
2. Call `prepare_publication`. It returns metadata, note Markdown, full transcript chunks, assets with absolute paths/digests, and existing receipts. It compresses audio into sequential MP3 parts under 10 MiB and splits large transcript attachments under that limit. Every asset is required; do not omit the transcript or audio. For text-only imports there is no recording.
3. Reuse the receipt's meeting Page if it exists. Otherwise search/list the parent's children for this local meeting ID before creating. Create an ordinary child Page titled `date — title`, under the exact parent Page ID, using the returned idempotency key. Include `Meeting ID: <id>` in its metadata paragraph. Do not pretend an ordinary child has the host's native meeting recorder/transcript binding. Immediately persist its Page ID/URL with `record_publication`, stage `page`. For an unknown creation outcome, inspect/recover before issuing a fresh creation.
4. Put notes in native Markdown; keep the summary visible. Add a full `Transcript` section with one paragraph per timestamped source segment, grouping long transcripts into reasonable blocks. `prepare_publication` returns chunks with pagination; read every chunk, never silently truncate. For long transcripts, nested Transcript child Pages are acceptable if needed to fit a hard Page limit; link them from the meeting Page. Also attach the complete transcript files.
5. Upload each missing asset with `write_page_reference`, passing its exact local `path` and the meeting Page ID. Require `file_access_confirmed: true`; retain its returned opaque `library-file:` or `project-file:` reference, digest, and byte size. Uploading does not insert a link. Persist each confirmed receipt immediately with `record_publication`, stage `asset`, matching asset name, digest, and returned `byte_size`, with `verified: true` only when upload access is confirmed. Saved receipts include this access confirmation and size; reuse them when their digest matches the current manifest. Do not upload again just because link insertion failed. For uncertain upload outcomes, inspect the destination's files before retrying.
6. Read the current Page and its guidance, then insert authorized file references as ordinary `[Recording • Part 01](library-file:...)` / `[Full transcript](library-file:...)` links. Native Pages do not support inline audio players. Use documented Markdown and returned file references, never local paths, data URLs, invented file IDs, or HTML audio players. Notes' evidence timestamps can point to the uploaded transcript file; the full transcript includes matching segment numbers.
7. Preserve edits/comments and rich blocks already on the Page. Use current block IDs/hashes and sequence guards for edits. Inspect every operation receipt, then read back the Page to confirm the meeting ID, notes, full transcript, and all asset references. Use `read_page_reference` to independently confirm the text transcript and its digest. That tool cannot read audio; for recordings, require the actual upload receipt's `file_access_confirmed`, matching digest/size, and saved Page link. Check the file viewer when available, and distinguish saved attachment verification from audio playback. A local save or an upload without a saved Page link is not publication.
8. Add a canonical Page link to the Meetings parent's meeting list, preserving prior meetings. Check for an existing link before appending. Remove the initial empty-state sentence only when a meeting has actually been published.
9. Call `record_publication`, stage `complete`, with the confirmed Page URL and `verified: true` only after the above checks. The server requires receipts for every prepared asset and the current transcript/notes revision. Return that URL. If any step fails, report the missing stage and retain cache/receipts for resumption. No automatic cache deletion, email, sharing changes, or action-item task launches.

Resume from receipts. Distinguish Page creation, asset upload, Page edits, parent indexing, and final verification. For stale guards, reread the affected block and rebuild only pending edits. For an unknown write outcome, inspect before retrying. If a corrected request fails again, stop that stage and report it.
